# 编码风格规范

适用：Java 源码、测试、配置及相关脚本。优先保持现有仓库的一致风格，不因局部改动重排无关代码。

## 格式与命名

- **CODE-01｜必须**：使用仓库指定且锁定版本的 formatter；CI 只检查，不自动修改源码。Checkstyle 不重复执行与 formatter 冲突的格式及 import 规则。
- **CODE-02｜必须**：包名全小写，类名 UpperCamelCase，方法和字段 lowerCamelCase，常量 UPPER_SNAKE_CASE；命名体现业务用途，避免泛化的 data、process 和无边界 manager。
- **CODE-03｜必须**：布尔字段使用 enabled、active 等明确名称，JavaBean getter 可以使用 isEnabled；hasPermission、canExecute 等语义方法允许使用。三态业务优先明确枚举，不混淆 null 与 false。
- **CODE-04｜推荐**：沿用项目的 Controller、AppService、Repository、Adapter 等角色命名；不为了满足后缀创建多余接口或类。

## 简洁与可读性

- **CODE-05｜优先**：先复用现有实现和标准库，再考虑新增依赖；没有实际隔离或复用需求时不增加工厂、基类、配置项和通用框架。
- **CODE-06｜必须**：函数职责清晰；固定业务值使用有语义的常量、枚举或配置。方法行数、参数个数和复杂度阈值作为仓库检查提示，不代替正确性判断。
- **CODE-07｜推荐**：简单对象直接构造，重复且复杂的转换再提取 Converter；不为未来可能的变化预建多套同构模型。
- **CODE-08｜必须**：公开接口、端口及复杂业务行为写清输入输出、空值、失败和必要不变量；注释解释原因、限制与特殊决策，及时删除过期注释。

## 数据与 Java 用法

- **CODE-09｜必须**：精确金额使用有明确精度、币种和舍入规则的十进制表示，通常为 BigDecimal；不通过二进制浮点构造精确金额。数值大小用 compareTo，值相等按规范化语义实现 equals/hashCode。
- **CODE-10｜必须**：业务时间使用 java.time；需要控制当前时间时注入 Clock 或传入时间；持续时长使用合适的单调计时机制。
- **CODE-11｜必须**：返回值及集合的空值语义明确；按约定返回空集合，避免将“没有结果”与“执行失败”都表示成 null。Optional 的使用沿用项目约定，不直接充当公开协议。
- **CODE-12｜必须**：字符串比较使用正确的值比较；equals/hashCode 保持一致。不可变对象的集合和成员需要防御性处理，record 本身不保证深不可变。
- **CODE-13｜必须**：拥有生命周期的资源正确关闭，优先 try-with-resources；不关闭由容器或共享组件拥有的客户端，不在 finally 中 return 或掩盖原始异常。

## 异常与日志

- **CODE-14｜禁止**：空 catch、吞异常、printStackTrace、将失败转换为伪造成功，或在重抛时丢弃原始原因。
- **CODE-15｜必须**：在合适边界将异常映射为稳定错误，记录必要上下文，避免每层重复打印同一堆栈；对外不泄露内部实现与凭证。
- **CODE-16｜必须**：使用 SLF4J 占位符或项目结构化日志方式；生产代码不依赖 System.out 排障。默认不输出完整请求、Prompt、Completion、工具报文、密钥及敏感身份信息。

## 注入、并发与调用

- **CODE-17｜必须**：Spring 管理组件使用构造器注入，适合保持不变的依赖使用 final；禁止字段注入。领域对象不以框架注入替代清晰构造。
- **CODE-18｜必须**：并发任务有执行器所有权、并发上限、排队／背压、超时、取消及拒绝策略；避免平台线程池的无界资源增长。虚拟线程同样限制下游并发和配额。
- **CODE-19｜必须**：异步与响应式路径正确传播并清理必要上下文，防止身份串线；不默认依赖公共线程池承载阻塞、长耗时或具有租户上下文的任务。
- **CODE-20｜必须**：避免无意的数据库 N+1、重复远程调用和无界重试。Agent 迭代与分页可以循环，但受明确终止、总期限和额度限制。
- **CODE-21｜必须**：不为通过格式、覆盖率或复杂度检查编写无意义代码；修改范围聚焦本任务，保留必要安全与数据完整性控制。

验收：仓库格式检查、实际启用的静态检查，以及与行为变化匹配的验证；不强制为纯格式或文档改动新增单元测试。
