# 基础设施层规范

适用：数据库、缓存、模型、工具、检索、消息、审计、执行恢复和可观测的技术实现。未启用的能力不要求额外建设。

## 技术适配与依赖

- **INFRA-01｜必须**：实现内层定义的端口，转换技术类型及错误；不得在适配器中自行决定业务优惠、风险放行或模型路由政策。工具入口桥接调用应用用例，不直接访问 Mapper。
- **INFRA-02｜必须**：创建客户端集中管理，按模型、区域及用途配置具名实例；共享连接资源，不共享可变单次请求状态。依赖版本与项目兼容矩阵一致。
- **INFRA-03｜必须**：外部调用配置连接／请求超时及总期限；按错误、幂等能力、剩余时间和预算决定有限重试，采用退避与抖动，避免多层重试放大负载。

## 数据库、迁移与缓存

- **INFRA-04｜必须**：使用参数化查询；动态字段、排序及表名采用白名单。关键唯一性由数据库约束保证，应用处理并发冲突，不以“先查再插”代替约束。
- **INFRA-05｜必须**：持久化实现不向外暴露 ORM／Mapper 类型。复杂领域与存储模型通过受控转换隔离；查询返回应用读模型，简单映射不强制额外转换框架。
- **INFRA-06｜必须**：明确字段类型、长度、金额精度、时间精度、索引及租户隔离；敏感文本和大结果有受控存储、摘要、授权与生命周期。
- **INFRA-07｜必须**：已应用的版本化迁移不直接修改，用新脚本修正；验证空库和受支持旧版本升级。区分版本迁移、可重复迁移、前向修复及备份恢复，不承诺所有 DDL 可回滚。
- **INFRA-08｜必须**：大表变更评估锁、数据量、复制和磁盘影响，依据数据库能力选择在线方案。数据删除和清理遵守保留策略，不一律永久软删。
- **INFRA-09｜必须（缓存）**：明确事实来源、键空间、访问控制、过期、失效及一致性窗口。缓存不可用与授权／幂等／预算存储不可用分别定义策略，不能统一放行。

## 任务、幂等与可靠交付

- **INFRA-10｜必须（可恢复任务）**：状态、待执行意图及结果可持久追踪；按安全 checkpoint 恢复，避免重复成功动作。多实例领取／接管采用原子机制及版本校验，拒绝过期工作者写回。
- **INFRA-11｜必须（外部写）**：幂等记录包含租户／主体、操作、键、请求摘要、状态、结果引用和期限；唯一约束处理竞争。相同键不同参数冲突，未知结果进入核对流程。
- **INFRA-12｜必须（外部写）**：核实外部系统是否实际支持幂等；不支持时使用外部查询、业务唯一约束、对账或人工核对。数据库执行权不能独自阻止外部重复动作。
- **INFRA-13｜必须（可靠事件）**：状态与 Outbox／发布记录同事务提交；发送可重试、消费可去重，监控积压及失败。普通 AFTER_COMMIT 监听不等于持久可靠交付。
- **INFRA-14｜必须（高风险动作）**：动作前可靠保存意图和授权证据；动作后记录结果，结果未知可核对。异步审计必须有持久可靠来源，不能只依赖内存队列。

## Spring AI、工具与检索

- **INFRA-15｜必须（模型）**：程序消费的输出依次验证解析、Schema、字段及业务语义；解析失败不伪造成功，不自动重做已执行的写工具。用量取实际响应元数据，缺失时标明未知。
- **INFRA-16｜必须（工具）**：每次请求只开放当前身份和任务允许的工具；执行前校验工具、参数、资源、当前授权及有效审批。可信身份和权限不能由模型参数决定。
- **INFRA-17｜必须（循环与 Advisor）**：验证实际 SDK 的自动工具循环和 Advisor 顺序，覆盖流式、拒绝、取消与多轮路径；单次检查或最外层过滤不能代替每次副作用授权。
- **INFRA-18｜必须（Prompt）**：记录执行时 Prompt、模型参数、工具 Schema、策略和编排版本／摘要；运行绑定可追溯配置，变更与回滚按兼容性验证，不要求全部热更新。
- **INFRA-19｜必须（记忆／RAG）**：存取实施租户和资源 ACL；conversationId 或向量元数据不是权限证明。区分合法空检索与检索服务故障，按产品证据要求输出结果。
- **INFRA-20｜必须（MCP／外部工具）**：锁定协议及 SDK，限制服务器、工具和出站目标；远端描述与行为注解不构成信任。工具或 Schema 变化需重新核验契约和权限。
- **INFRA-21｜必须（沙箱）**：不可信代码使用与威胁模型匹配的隔离，限制身份、文件、网络、CPU、内存、进程和时间，不携带生产凭证；普通子进程不自动等于安全沙箱。
- **INFRA-22｜必须**：检索材料、工具输出及第三方文档视为不可信数据；模型外实施授权、参数、出站及数据控制，防止提示词注入、SSRF、路径穿越和命令注入。

## 可观测与验证

- **INFRA-23｜必须**：密钥受控注入，不进入代码、Prompt、日志或 Trace；诊断数据默认不存完整敏感报文，采样有脱敏、访问及保留限制。
- **INFRA-24｜必须**：记录必要错误、延迟、重试、执行状态、预算和积压；指标标签有界，不默认加入无限增长的用户／任务／会话标识。精确计费以账本为准，不依赖监控 Counter 结算。
- **INFRA-25｜必须**：按线程和响应式技术栈传播及清理上下文；Trace 可通过关联 ID／Link 连接恢复任务。告警对应影响、负责人及处理手册，不代替执行前额度拦截。
- **INFRA-26｜必须**：验证真实数据库约束、迁移、映射、并发及必要故障路径；测试依赖配置完整。按风险检查超时、未知结果、重复投递、恢复和隔离，不只验证正常连接。
