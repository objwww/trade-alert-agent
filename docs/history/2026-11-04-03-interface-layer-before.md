# 接口层规范

适用：HTTP、RPC、SSE、消息入口、任务入口及启用时的 A2A 协议适配。

## 职责与契约

- **API-01｜必须**：入口只负责协议转换、结构校验、可信身份提取及调用应用用例；不直接操作聚合、SQL、Mapper、模型或工具客户端，不承载业务长事务。
- **API-02｜必须**：对外契约明确字段语义、类型、单位、默认值、必填条件、枚举、错误、分页、授权和幂等；权威定义放 OpenAPI、Schema 或项目 Spec，避免多处重复维护。
- **API-03｜必须**：请求与响应不直接暴露领域聚合或数据库实体，返回字段采用明确允许集合；不可变 DTO 优先，record 按兼容需要选择。
- **API-04｜推荐**：简单 Request → Command、Result → Response 直接转换即可；复杂重复转换提取 Assembler。领域到存储的转换留在对应内部边界。

## 校验与授权

- **API-05｜必须**：入口校验类型、格式、长度、范围、请求大小及允许字段，业务不变量由领域行为保证；动态排序字段、URL 等额外执行允许范围校验。
- **API-06｜必须**：租户、用户、代理身份和权限取自可信上下文，不信任请求或模型自报；任务查询、流订阅、重连、取消与产物下载分别验证资源归属和访问权限。
- **API-07｜必须**：认证与资源授权分开落实；前端隐藏按钮、难猜的 ID 和包含 tenantId 的键均不构成授权机制。

## 响应、错误和兼容性

- **API-08｜必须**：HTTP／RPC 状态与业务错误契约一致，错误有稳定机器标识和可行动描述；不把所有失败包成 HTTP 200，也不泄露堆栈、密钥或内部地址。
- **API-09｜必须**：普通 JSON 使用项目选定的响应风格；SSE、文件和第三方协议遵循各自契约，不强制套 Result<T>。
- **API-10｜必须**：可能增长的列表定义分页、最大返回量和稳定排序；说明空结果、末页及并发更新下的可见性。
- **API-11｜必须**：稳定版本不直接删除字段、修改类型、增加必填入参或悄悄改变语义；新增字段、枚举和默认行为评估旧客户端。破坏性变化明确迁移、版本及退场方案。
- **API-12｜必须（可重试写接口）**：定义幂等键或业务唯一键、去重范围、有效期及重复请求响应；相同键不同参数冲突，在途返回处理中／任务句柄，成功后返回已有结果。

## 长任务与 SSE

- **API-13｜必须（长任务）**：按网关、连接和客户端期限决定异步化；返回任务标识和查询方式。不要把固定 10 秒当成所有系统的阈值。
- **API-14｜必须（取消／恢复）**：区分取消请求已受理、后续执行已停止和外部动作已发生；只公开已验证的 pause/resume 能力，不承诺撤销已完成副作用。
- **API-15｜必须（SSE）**：定义事件类型、ID、顺序、重连游标、保留窗口、重放及慢消费者策略；重连不得重复执行模型或工具操作。
- **API-16｜必须（SSE）**：响应头提交后的异常采用流内错误事件或已定义的断流语义；不能期待全局异常处理器把已发送的流改写为 JSON。流结束、失败和取消均释放资源。
- **API-17｜必须（SSE）**：说明断开订阅是否取消任务；任务执行与多次订阅解耦，防止每个订阅者重启一次任务。

## 协议适配与验证

- **API-18｜必须（A2A）**：锁定协议、SDK 及传输绑定，按该版本验证发现信息、授权、任务、流和错误；不混合不同版本端点。Agent Card 不包含凭证或内部敏感信息。
- **API-19｜必须（消息入口）**：验证消息来源、Schema、租户和重复投递；定义重试、顺序需求及失败处理，通过应用用例处理业务，不绕过统一授权与去重。
- **API-20｜必须**：行为变化验证结构校验、未授权访问、响应及错误契约；涉及兼容、幂等、异步或流时补充对应场景，不只验证成功路径。
