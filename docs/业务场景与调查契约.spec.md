# 业务场景与调查契约 Spec

版本：0.1｜日期：2026-11-02｜状态：待评审的候选契约。适用“面向谷粒商城的证据驱动 RCA 调查平台”。本 Spec 为目标一的设计产物；后续实现应以评审通过版本为准，现有 Rules 持续有效。

## 1 业务词典与场景范围

### 1.1 统一术语

| 术语 | 精确定义与边界 |
| --- | --- |
| 故障场景 ScenarioDefinition／ScenarioVersion | 可复现或可回放的业务现象定义及不可变版本；不是已经发生的故障 |
| 故障触发 FaultTrigger | 一次注入申请及其执行、效果与恢复记录；包括被拒绝、未生效及结果未知 |
| 告警信号 AlertSignal | 来源系统对规则或异常的实际观测，保留原始来源 ID；重复信号不是新的根因 |
| 事件 Incident | 在明确环境、业务范围和时间内需要调查的一次异常事件；可关联多条告警和多次调查 |
| 调查 InvestigationRun | 为某一 Incident 执行的一次独立调查，固定配置、权限范围与预算 |
| 计划 PlanRevision／PlanMembership | 不可变任务 DAG 版本，以及该版本实际接受的 Task 集合 |
| 任务 InvestigationTask | 一个具备目标、完成条件与授权范围的调查问题，不等于一次 HTTP 请求 |
| 尝试 TaskAttempt | 某 Task 一次实际执行身份；重试、接管均保留新尝试及旧历史 |
| 调用 ToolCall／ProviderAttempt | 一次已保存的逻辑工具意图，以及底层一次实际请求；二者不能混计 |
| 证据 Evidence | 有来源、查询范围、采集时间、完整性和内容定位的材料；ID 不授予访问权 |
| 发现 Finding | 针对明确命题的结构化观察／判断，以及支持、反证和缺口；不是自动成立的根因 |
| 审核 ReviewResult／ReviewIssue | 对某版候选及状态的审核记录、具体问题及解决状态 |
| 根因报告 RCAReport | 某 Run 下的候选解释、支持／反证、覆盖缺口、验证等级及建议；支持多个促成因素 |
| 测试 TestRun | 验证功能或模型行为的一次测试，关联调查、故障及证据，拥有独立测试结果 |

Incident 与领域事件不是同一概念。领域／集成事件表示“调查已申请”等已发生事实；审计记录表示谁对什么做了什么；本方案没有采用以事件重建全部状态的 Event Sourcing。

### 1.2 首批场景与优先级

| 中文场景 | 服务／领域 | 可观察现象 | 最小证据与允许结论 | 前置条件 |
| --- | --- | --- | --- | --- |
| 订单实例退出导致下单失败 | gulimall-order／交易域 | 下单请求失败、目标实例不可用 | 请求失败＋实例身份／健康＋时间关联；定位到容器与主机，原因不足则只报告不可用 | 第一闭环；目标二、三提供业务基线与实例映射 |
| 库存调用延迟导致订单提交超时 | gulimall-ware 与调用方／库存域、交易域 | 订单等待库存调用，耗时升高 | 依赖 Span、下游基线及日志；区分下游退化与订单本地等待 | 第二批；受控延迟和调用链就绪 |
| 订单消息消费异常导致订单状态延迟 | gulimall-order 消费角色／交易域 | 消息积压、消费异常、状态更新延迟 | 消费指标＋错误记录＋业务关联；解析失败不能直接证明发布致错 | 第二批；消息路由、消费角色和测试数据就绪 |
| 数据库锁等待导致订单处理阻塞 | 订单服务及其数据库／交易域 | 请求等待、锁／事务占用异常 | 活跃等待链、事务和请求关联；区别锁等待、连接池耗尽与数据库不可达 | 受控数据与数据库只读诊断权限就绪 |
| 错误配置发布后订单处理退化 | 订单服务／交易域 | 变更后异常出现 | 发布／生效配置＋异常字段／行为关联＋反证；只有时间邻近则不确认因果 | 变更记录和受控配置回退方式就绪 |
| 支付回调结果未知导致订单待核对 | 订单服务及外部支付依赖／交易域 | 支付与订单记录暂不一致 | 支付状态查询、回调和订单状态；保留未知，禁止通过重复扣款验证 | 隔离支付模拟／沙箱与安全数据就绪 |
| 观测数据缺失导致调查证据不足 | 诊断能力／运维域 | 查询为空、采集失联或过期 | 明确区分 EMPTY、FAILED、STALE；输出缺口，不宣称业务正常 | 对照场景，不注入业务故障 |
| 实例重建导致历史与当前目标不一致 | 资源解析能力／运维域 | 名称／IP 相同但容器身份变化 | 历史与当前身份及有效期；阻断针对旧指纹的操作建议执行 | 安全场景；不因查不到旧容器扩大到整机 |

这些均为未执行的定义，不表示已具备注入条件。场景目录另见 [附件](附件/场景目录.json)。具体阈值不在目标一臆定，场景版本必须在运行前绑定有效基线、流量前提、观察窗口及证据要求。

服务词典以实际模块和部署为准：gulimall-order 显示为“订单服务”，gulimall-ware 显示为“库存服务”；“订单消息消费者”首先视为订单服务的逻辑角色，不假设已有独立消息微服务。“支付服务”在历史设计中是示意标签，新增记录应区分订单支付处理与真实外部支付提供方。历史图和编号原样保留，实际映射以目标二／三核实结果发布版本。

## 2 聚合边界、关系与可信字段

| 聚合／对象 | 拥有的规则与数据 | 关联方式 |
| --- | --- | --- |
| ScenarioDefinition | 中文定义、版本发布、适用范围；已发布版本不可原地改 | 被 FaultTrigger／TestRun 引用；真值区与模型可见区分开 |
| Incident | 业务范围、告警关联、公开编号、人工认领／关闭及当前被选报告引用 | 一对多 Run；无大日志、模型会话和全部任务列表 |
| InvestigationRun | 生命周期、阶段、权限快照、预算、Owner／Epoch、当前计划／状态版本 | 独立表关联 Plan、Task、Review、Report；避免全量 JSON 聚合写回 |
| InvestigationTask | 不可变目标与范围、完成条件、依赖、执行生命周期 | 一对多 Attempt；parentTaskId 是派发来源，不自动代表调度依赖 |
| Evidence | 来源与内容元数据、READY／有效性、精确引用和访问控制 | Finding 通过 EvidenceCitation 关联；正文和大对象独立存储 |
| Finding／ReviewResult | 不可变正式结果和来源版本；修正通过新版本／失效原因 | 由 StateCommitter 在必要短事务中与 Task／Run 版本一起提交 |
| InvestigationNote／ContextSnapshot | 从已提交状态派生的模型上下文与索引 | 可重建；不作为权限、证据、预算或工具是否执行的真源 |
| TestRun／FaultTrigger | 各自触发与结果生命周期、发起／执行身份和证据 | 通过带租户／环境的关联表连接，不嵌入 Run 取代其状态 |

一个 Incident 可有多个 Run，包括独立复查与评测对比；同一意图的重复创建通过幂等键去重，不设“Incident 天生只能一个活跃 Run”的领域红线。每个 Run 产出自己的报告，后完成的 Run 不自动覆盖 Incident 已选报告。发布／替换当前报告需要显式命令、授权与 expectedIncidentVersion；冲突保留两份结果供复核。

由服务端补充可信字段：tenantId、发起／执行账号、委托链、runId／taskId／attemptId、时间、权限决策、版本及 Epoch。模型的 FindingProposal 只提出命题及引用，不得自行声明这些字段来获得执行资格。

Task.scopeVersion、工具目录、模型／Prompt／Skill 版本及数据策略在执行时绑定。计划沿用旧 Task 时检查 membership 和任务契约是否仍相同，不以 createdPlanRevision 等于当前 revision 作为唯一资格条件。

## 3 状态维度与迁移

### 3.1 Run 生命周期与阶段

生命周期 status：QUEUED、RUNNING、CANCELLING、COMPLETED、FAILED、CANCELLED。

阶段 phase：NONE、PLANNING、EXECUTING、REVIEWING、FINALIZING。QUEUED 和终态 phase=NONE；RUNNING 可处于各工作阶段；CANCELLING 只能 FINALIZING。历史阶段写时间线，终态不靠保留 phase 冒充仍在执行。

| 当前状态 | 命令／已提交事实 | 前提 | 目标状态 | 冲突与重复 |
| --- | --- | --- | --- | --- |
| 不存在 | 创建调查 | 当前授权、合法 Incident、固定配置、幂等键 | QUEUED／NONE | 同键同摘要返回原 Run；同键异摘要冲突 |
| QUEUED | Worker 领取 | 原子领取并授予新 Owner／Epoch／Lease | RUNNING／PLANNING | 其他 Worker 不能取得同一有效执行权 |
| RUNNING／PLANNING | 计划提交 | 基础版本、范围、DAG 与预算合法 | RUNNING／EXECUTING | 失败保留旧有效计划；无合法计划则失败或受控收尾 |
| RUNNING／EXECUTING | 满足审核准入 | 必要分支终止、已有结构化结果 | RUNNING／REVIEWING | 调查无确定结论也可审查缺口 |
| RUNNING／REVIEWING | 需要补证 | 新的可执行补证路径、预算与授权有效 | RUNNING／PLANNING | Reviewer 只提出问题，不直接创建任务 |
| RUNNING | 正常／有界结束 | 完成契约或预算／无进展停止；收尾已持久化 | COMPLETED／NONE | outcome 可 INCONCLUSIVE；不强行确认根因 |
| QUEUED | 取消请求 | 有权限且未被执行者抢先推进 | CANCELLED／NONE | 与领取竞争由数据库条件更新裁决 |
| RUNNING | 取消请求 | 合法权限、版本 | CANCELLING／FINALIZING | 停止新派发，传播取消，保留未知外部调用 |
| CANCELLING | 调查推进已封闭 | 不再允许当前调查推进，已记录各 Attempt／未知调用 | CANCELLED／NONE | 不承诺远端 HTTP 已终止；未知项仍可由核验流程记录 |
| QUEUED／RUNNING／CANCELLING | 无法完成契约的系统性故障 | 记录原因与已有材料，完成可行收尾 | FAILED／NONE | 数据库提交失败时仅返回未知，不捏造已落库终态 |
| 任意终态 | 旧回调／重复结束 | 查询已有正式结果 | 原终态 | 不重新打开；新调查创建新 Run |

Run.outcome：NOT_EVALUATED、CANDIDATE_ACCEPTED、INCONCLUSIVE、NO_REPRODUCIBLE_ANOMALY。最后一项须有足够覆盖范围内的观察依据，“没有查到日志”不构成充分依据。terminationReason 单独说明完成、取消、预算、期限、无进展或技术故障。

CANDIDATE_ACCEPTED 表示候选达到报告证据要求，不自动证明所有因果链已受控复现。报告另记 verificationLevel（OBSERVED／EVIDENCE_SUPPORTED／CONTROLLED_VALIDATION）和各命题的缺口。

### 3.2 Task／Attempt／结论分离

Task.status：PENDING、RUNNING、SUCCEEDED、FAILED、SKIPPED、CANCELLED、SUPERSEDED。PENDING 的 Ready 资格动态计算，不增加可被入口随意设置的 READY 状态。

Attempt.status：CREATED、RUNNING、SUCCEEDED、FAILED、CANCELLED、ABANDONED、NOT_STARTED。线程池拒绝时记录 NOT_STARTED 并补偿任务领取；接管创建新 Attempt，不修改旧 Attempt 的身份和 Epoch。ABANDONED 不证明旧外部调用已停止。

TaskExecutionResult 分别保存 executionStatus、coverage（FULL／PARTIAL／NONE／UNKNOWN）及 conclusion（SUPPORTED／REFUTED／INCONCLUSIVE／NOT_EVALUATED）。正常查询且未找到原因可为 SUCCEEDED＋FULL＋INCONCLUSIVE，不因此技术重试。

依赖条件明确为 EXECUTION_TERMINATED、EXECUTION_SUCCEEDED 或 REQUIRED_EVIDENCE_READY，并保存所需证据要求；解析结果 SATISFIED／WAITING／IMPOSSIBLE。汇总任务可以接受已终止且无结论的分支，必需证据任务不能跳过要求。

条件逐条绑定依赖边，不用一个全局条件覆盖所有上游。一个汇总任务可以同时要求日志分支已终止、配置分支已取得指定 READY 证据；无依赖任务的 dependencies 为空。parentTaskId 仅表示派发来源，不自动创建依赖边。

Task 迁移：PENDING 领取为 RUNNING；Attempt 成功且满足任务完成条件则 SUCCEEDED；可安全重试的 Attempt 失败且仍有预算时，记录旧尝试后回 PENDING；不可重试或重试耗尽才进入最终 FAILED。上游要求已不可能满足时，按任务契约 SKIPPED 或 FAILED；取消／计划替换分别进入 CANCELLED／SUPERSEDED。SUCCEEDED、FAILED、SKIPPED、CANCELLED、SUPERSEDED 为本版 Task 终态，不原地重开。重试终态业务目标需创建新 Run 或新计划 Task 并关联来源；接管尚未终结的 Task 保留其业务身份，创建新 Attempt。

### 3.3 证据、审核与业务恢复

Evidence.status：PENDING、READY、UNAVAILABLE、EXPIRED、INVALID、DELETED；completeness：COMPLETE、TRUNCATED、SAMPLED、UNKNOWN。只有已正式 READY 且适用的证据可被正式 Finding 引用；元数据存在不等于内容可读取。读取失败与采集无效、源过期分别处理。隐私删除可改变可用性，但保留允许保留的引用与删除原因。

ReviewDecision：ACCEPT_CANDIDATE、NEEDS_EVIDENCE、REJECT_CANDIDATE、INCONCLUSIVE。每个 Issue 有 OPEN／RESOLVED／UNRESOLVABLE。审核绑定被审报告／状态版本；出现影响结论的新证据须重新核验适用性，不能仅因其返回较晚覆盖当前状态。

Incident.status：OPEN、INVESTIGATING、MONITORING、RESOLVED、CLOSED。FAILED Run 不自动关闭 Incident；RESOLVED 要有实际业务恢复验证引用；人工 CLOSED 可表示停止处理，必须显示关闭理由及“恢复未核验”。多个 Run 的生命周期不直接回写为同一个 Incident 状态。

Incident 迁移：OPEN 经调查受理进入 INVESTIGATING；已有缓解且等待业务验证时可进入 MONITORING；OPEN／INVESTIGATING／MONITORING 只有取得业务恢复验证才可进入 RESOLVED。人工有权关闭可进入 CLOSED，保留原因与恢复状态。CLOSED 默认不再接收新调查，重新处理需显式授权重开命令；旧 Run 仍可受控收尾，不因关闭自动假装被取消。恢复后再次发生通常创建新 Incident，并用 previousOccurrenceRef 关联；同一事件的纠正重开须保存原因，不删除旧恢复记录。

## 4 编号、时间、资源与引用

公开编号格式：中文事件或行为-中文服务-中文领域-YYYYMMDD-至少六位递增序号。例如“订单提交失败-订单服务-交易域-20261102-000001”。每段来自受控词典且不含分隔符；内部 UUID、业务公开编号、源系统 ID 和告警／请求指纹分别存储。

计数器按 tenant＋objectType＋稳定事件／服务／领域代码＋分配日分桶，在创建对象同一短事务中原子分配，唯一约束兜底。日期按 Asia/Shanghai，允许空号；超过六位增长不截断。不承诺跨桶时间排序，不在公开编号中加入真实订单号或个人信息。正式编号不可因资源定位纠正而重写，另存实际影响范围与别名。

时间戳按 RFC3339 接收并转换 UTC，存储精度至微秒；超过支持精度返回校验错误，避免静默精度丢失。事件发生、采集、接收、入库时间分别保存，来源时钟偏差与迟到情况标注，不能凭接收时间推定变更先后。

ResourceRef 保存 environmentId、serviceId、role、hostId、instanceId、containerId／systemdUnit、imageDigest／deploymentVersion、validFrom／validTo、observedAt 和 source。Docker 完整 containerId 在实际执行目标校验时须为 64 位十六进制；名称和 IP 仅作显示。证据定位不完整可以开展有限调查，但不得输出“目标已确认可执行”的建议。

EvidenceCitation 由 evidenceId、locator、supportedClaimId 构成。locator 对日志引用快照记录或行范围，对 Trace 引用 traceId／spanId，对指标引用序列标签、时间窗与数据点范围；不得接受模型自由传对象存储路径或 URL 代替授权读取。

## 5 核心不变量及责任边界

1. 所有读写按可信租户／环境授权；ID、前端按钮和模型自报身份不构成授权。
2. 同一 Run 同时仅有一个有效 Owner；Run 内 Task 可有界并行，不共享可变模型消息列表。
3. 计划／状态版本、Epoch、Attempt、当前任务成员资格均参与结果提交检查；普通追加冲突可重读合并，过期执行者不能重试越过 fencing。
4. 授权范围不得由 Replan、专家、Skill、MCP 描述或日志内容扩大；权限撤销后不继续发起新查询，已取得证据也按当前访问政策读取。
5. ModelTurn 和全部 ToolCall Intent 在外部派发前可靠保存；逻辑调用与 ProviderAttempt 分开记录。
6. Evidence、Task 状态、Finding、Checkpoint 等本库可原子部分按短事务提交；模型和外部 I/O 在事务外。
7. 工具 UNKNOWN 不当失败重放；只读调用按当前授权／预算有限重查并保留新的采集事实，写动作先对账。
8. 任务成功、证据覆盖、假设成立、审核接受、故障恢复各有独立事实。
9. 故障触发真值、预期答案和评判标签不进入被测 Agent 的 Context；测试执行身份也不自然拥有真值读取权。
10. 每次正式测试先经平台登记身份、版本与中文功能；截图不适用要有原因及原生证据。平台未实现前的文档核验如实标记外部执行。
11. 场景和运行固定契约／模型／Prompt／工具／Skill／策略版本；已发布版本不原地变更，已有运行不混用一半新配置。
12. Incident 当前报告通过显式版本化选择发布，多 Run 结果独立保留，不以最后写入为准。
13. 故障注入与恢复由受控实验能力实施，独立于被测诊断 Agent；RCA 输出修复建议不授予执行权。
14. 证据或判断变化用新记录、补充或失效标记解释，压缩与计划变更不删除历史事实。

### 5.1 初始授权矩阵

| 身份能力 | 允许范围 | 不自动获得的能力 |
| --- | --- | --- |
| 查看者 | 当前租户／环境授权的监控、事件和脱敏报告 | 创建调查、触发故障、读原始真值 |
| 调查操作者 | 授权事件的创建／取消调查及证据查询 | 任意服务查询、生产写操作、报告发布 |
| 测试操作者 | 平台测试登记、隔离环境内获授权的故障申请 | 评测答案读取、跨环境或整机操作 |
| 场景维护者／真值评判者 | 各自授权的场景版本维护／真值与评判 | 将真值输入被测 Agent；审批不会代替执行授权 |
| 报告发布者 | 复核后显式选择事件当前报告 | 修改原始证据、覆盖其他 Run 的结果 |
| Worker／连接器服务身份 | 被分配任务及有效租约内的受限能力 | 交互式全主机权限、任意租户或默认 Shell |

角色名是能力分组候选，真实账号与身份提供方由后续目标接入；角色可组合，但数据范围和任务权限仍取交集。管理员配置权限不默认等于跨租户数据读取权限。接口、流订阅、证据片段和截图下载各自鉴权；授权服务不可用不默认放行。租约到期以数据库时间判定，续租失败或执行权不确定时停止新派发，Epoch 仍需在提交时核验。

## 6 契约版本与后续目标交接

附件 Schema 约束结构；唯一性、授权、DAG、状态转换、交叉引用、证据支持及业务恢复由服务端语义规则保证。format 是否执行需验证器显式启用。目录中的示例仅为合成定义，无真实执行结果。

目标二接收服务词典、环境清单、版本锁定要求；目标三接收 ResourceRef 与证据来源要求；目标四接收 TestRun／FaultTrigger 关联及真值隔离；目标五接收 AlertSignal／Incident 幂等边界；目标六接收工具及证据协议；目标七接收 Run／Task／Attempt、状态与并发不变量；目标八、九接收任务结果与审核协议；目标十、十一接收计划成员关系、上下文与恢复约束；目标十二接收展示和验收字段。

新增字段不自动视为兼容：请求严格拒绝未知字段，响应演进需验证既有客户端处理未知字段和枚举的行为。严格 Schema 的消费者绑定明确版本；破坏性变化采用新契约版本并保留旧运行解释器。不得把旧运行直接改写为新枚举以掩盖迁移缺口。
